# Version Control Systems
Version control systems are software tools that help software teams **keep track and manage changes to source code** over time.
- Change history recording
- Independent development
- Storage management
## Repositories
- **Repository**: files/folders that contian projects files **and each file's version history**
- **Local repository**: stored on a developer's computer
- **Remote repository**: stored on some remote computer/server, all team members have access

#### Advantages
- Flexibility for local work without network connection
- Speed to perform commands on local repository
- Resilience to restore damaged remote repo 
#### Disadvantages 
- Storage: Big projects can take up a lot of disk space on local Development environments

## Pull-based development 
When you don't have access to the remote repository you can fork it to a personal github repository and work on that.
- Then if you think you can contribute to the original repository you have no access to, you can create a pull request

# Free Software
An ethical imperative to **respect the users' freedom
Software that fulfills the following criteria:

0. The freedom to run the program as you wish, for any purpose
1. The freedom to study how the program works, and change it, so it does your computing as you wish. **Access the source code** is a precondition for this
2. The freedom to redistribute copies as you can help others in your community
3. The freedom to distribute copies of your modified version to others. By doing this, you an give the whole community a change to benefit from your changes. Access to the source code is a precondition to this

## Open Source 
A more loose criteria than **Free Software** 
Considers issues in terms of **how to make software "better"** in a practical sense only
